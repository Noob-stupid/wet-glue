# 胶水 glue

> 管理"拿不准的代码"。两行注释框住一块代码，它就是可替换的——用别的实现把它换掉，跑基准，挑最好的，然后**固化**焊死。

## 它解决什么问题

写代码时总有一块"还没想清楚"的逻辑：索引到底用 B+ 树还是红黑树？序列化用 JSON 还是 MessagePack？缓存用 LFU 还是 LRU？

传统做法是抽接口、配 DI、上 Feature Flag……重且侵入。胶水换了个思路——**用头尾两行注释把这块代码框起来**，切换直接改源码文本。运行时零间接层，固化了就是普通代码。

```
    public String get(int key) {
        // glue:begin lookup            ← 头
        return rbtree.get(key);          ← 拿不准的这块
        // glue:end                      ← 尾
    }
```

## 三步上手

**1. 标记** —— 在拿不准的代码前后各加一行注释（上面的写法）。

**2. 扫描 + 登记候选**：
```bash
glue scan                    # 发现所有胶水区域
glue add lookup bplus        # 把当前代码另存为候选实现 "bplus"
```

**3. 切换 → 跑测试 → 固化**：
```bash
glue use lookup bplus        # 切到 B+ 树实现（源码被文本替换）
<跑你的测试/基准>             # 对比两个实现
glue use lookup rbtree       # 切回红黑树
glue seal lookup             # 锁定最优实现（二次确认，焊死代码）
```

## 命令速查

| 命令 | 作用 |
|---|---|
| `glue scan` | 扫描源码，登记所有胶水区域 |
| `glue list` | 列出区域、状态（experimental / candidate / sealed）、候选，以及"胶水干了没" |
| `glue add <区域> <别名>` | 把区域当前内容另存为一个候选实现 |
| `glue use <区域> <别名>` | 切换到某个候选实现（源码替换，无运行时开销） |
| `glue refs <区域>` | 查看这块代码对外的隐式契约（读了什么、写了什么） |
| `glue seal <区域>` | **固化**：二次确认，移除标记，代码焊死（开销严格为 0） |
| `glue unseal <区域>` | 解固化：重新插入标记，可再次切换 |
| `glue verify <区域> [命令]` | 登记/执行该区域的验证命令（切换后一键编译+跑测试） |
| `glue check` | 校验漂移 / 胶水外泄（CI 用，有问题退出码 1） |

## 机械差异怎么处理（签名不同、换依赖）

换上的实现若**对外依赖变了**（比如从 `rbtree.get()` 换成 `bpKeys` 二分查找），切换前工具会先亮出差异：

```
⚠ 候选实现对外契约有差异（rbtree → bplus）：
  + 新增读取: bpKeys, bpVals
  - 不再读取: rbtree
```

- **符号级的改名/换依赖**：切换前就可见，你扫一眼确认。
- **类型级差异**（方法签名、返回类型真不同）：工具提示你跑 `glue verify`，编译器精确报出差在哪，你据此在候选片段里补适配（适配就是普通代码，写进片段即可）。
- **固化前强制验证**：登记过验证命令的区域，`seal` 时会先自动跑一遍，失败则**禁止固化**（对应 v1.0 §4.2「固化 = 测试通过 + 人工确认」）。

## 一键验证（简单操作）

切换实现后要确认行为没变——`glue verify` 把"编译 + 跑测试/基准"收成一条命令：

```bash
glue verify lookup "javac -encoding UTF-8 -d out IndexStore.java && java -cp out IndexStore"  # 登记一次
glue use lookup bplus      # 切换后，工具会提示你可一键验证
glue verify lookup         # 一键执行已登记的命令，通过/失败退出码正确透传
```

命令里的 `{root}` 会替换成项目根目录绝对路径。验证失败时退出码非 0，可直接接进 CI。

## 运行

Windows 双击入口是 `glue.cmd`；Git Bash / Linux / macOS 用 `./glue`。首次运行自动编译，之后直接跑。

## 设计要点

- **无运行时开销**：切换发生在构建/编辑期，产物里没有任何间接层。固化即"普通代码"，严格等价于手写。
- **状态自动流转**：登记后 `experimental`；有 ≥2 个候选对比时 `candidate`；`seal` 后 `sealed`；`unseal` 回到 `experimental`。
- **防误固化**：固化需二次确认；`CI` 环境变量存在时拒绝固化（强制人工在本地确认）。
- **全程留痕**：每次变更写入 `swappable.lock`，纳入版本控制。
- **胶水会"干"**：`list` 里提示距上次切换的天数。长时间不动的胶水提示你该决定固化了。
- **胶水泄漏检测**：`check` 会报"区域内部声明的名字被区域外引用"——这种区域整块无法替换，等于胶水漏了。

## 目录结构

```
glue/                  # 一键入口（bash）
glue.cmd               # 一键入口（Windows cmd）
src/Glue.java          # 工具本体（单个文件，Java 17）
examples/demo/         # Java 示例：红黑树 vs B+ 树
examples/csharp/       # C# 示例：同一套工具管理 C# 代码
.glue/<name>/          # 每个区域的候选片段(.frag) + 元数据（提交到 git）
swappable.lock         # 审计日志（提交到 git）
```

## 支持哪些语言的代码

被管代码要求**行注释是 `//` 的语言**——标记与引擎逻辑完全一致，工具按文件扩展名识别，零引擎改动：

`.java` `.cs` `.kt` `.go` `.ts` `.js` `.c` `.cpp` `.rs` `.swift` 等（`src/Glue.java` 里的 `SRC_EXT` 集合，加新语言只需加一行）。

`examples/csharp/` 有完整的 C# 演示：同一个工具、同一套 `// glue:begin` 标记，在 C# 项目里登记、切换、`glue verify` 一键跑 `dotnet run` 全流程可用。
（行注释是 `#` 的语言如 Python/Shell 需改标记约定，属 v2。）

## 设计边界（当前版本）

- 头尾标记是**同一语言内的代码替换**。若调用方与实现方是不同语言/运行时（如 Python 算法换 Rust 实现），本工具不适用——那属于 IDL + 服务化范畴。
- 固化的实现选择**没有编译器保护**：两个候选读取/写入的外部名字不同，工具只能提示（`refs`、`check`），不能替你保证正确。这正是"未固化"的代价，也是你应该亲自跑测试的原因。

## 后续扩展方向

- **`#` 注释的语言**（Python / Shell / Ruby）：标记约定不同（`# glue:begin`），需在标记识别处做语言分支——是下一个真正要动引擎的扩展点。
- **固化剪枝 / 构建集成**：把"切换到某实现"接进 Maven/Gradle/dotnet 构建，切换后自动重编译验证。
- **风险分级**：按"区域被多少外部点引用 + 是否有序列化耦合"给每个胶水打风险分，高风险的切换强制先 `verify`。
